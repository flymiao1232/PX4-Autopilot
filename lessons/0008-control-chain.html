第 8 课 · 控制链路

Mission:能独立改 PX4 代码 2026-11-05 · 约 35 分钟 · 路线:课程地图 · 上一课:第 7 课 · 图:控制链路图 · 术语:术语表

阶段三第一课。改控制是"改 PX4"的深水区,而动手前的门票是看懂数据怎么流。这一课不写新代码,练一个更值钱的能力:把多旋翼控制链路从官方概念图钉到你电脑上这个正在跑的 PX4——每个环节用 uORB 实测、用源码行号定位。对应官方 Flight Stack Architecture 与 Control Allocation。

第 0 步 · 热身:未解锁时控制环在跑吗?(5 分钟)

起 SITL(不起飞、不解锁),直接看:

pxh> uorb top
pxh> listener actuator_motors

两个观察:① 锁定的(没解锁)无人机,actuator_motors.control[] 全为 0——控制环其实在跑,只是输出在解锁前被抑制;② uorb top 里 vehicle_rates_setpoint、vehicle_torque_setpoint 这些 topic 都在持续发布。控制是连续的,解锁只是一个"放行"开关(vehicle_control_mode)。

一、一条链,五个环节

对照控制链路图读一遍,核心链条:

vehicle_attitude_setpoint(姿态期望)
  → mc_att_control(姿态外环,P)          → vehicle_rates_setpoint(角速度期望)
  → mc_rate_control(角速度内环,PID)     → vehicle_thrust_setpoint + vehicle_torque_setpoint
  → control_allocator(控制分配)         → actuator_motors(每电机 0~1)
  → pwm_out_sim → gz 电机 → 机体 → IMU →(回到内环,闭环)

三个已在 v1.17 源码核实的非显然事实:

  • ⚠️ 内环输出不是 actuator_controls_0。老教程、老论文里"控制器输出 actuator_controls"的写法已过时——v1.17 的 mc_rate_control 发布的是 vehicle_thrust_setpoint + vehicle_torque_setpoint两个 topic(mc_rate_control/MulticopterRateControl.hpp:110-111,发布点在 MulticopterRateControl.cpp:260/264)。查资料对不上时,源码是终审。
  • 控制环没有"配置文件里的频率",节拍器是数据本身。每个环用 SubscriptionCallbackWorkItem 订阅上游 topic,数据一到就唤醒自己:mc_att_control 由 vehicle_attitude 唤醒(mc_att_control.hpp:113),mc_rate_control 由 vehicle_angular_velocity(陀螺仪)唤醒(MulticopterRateControl.cpp:126)。所以频率是量出来的,不是配出来的——内环最快,级联向下。
  • 控制器不直接算电机,中间有"控制分配"层。control_allocator 订阅推力+力矩设定点,解一个分配问题:给定 x500 的 4 个电机布局(CA_ROTOR* 参数,第 7 课机架文件里见过),每个电机该转多快(ControlAllocator.hpp:178-187)。换机型只换机架文件,控制器代码一行不动——这就是分层的意义。
📌 读任何 PX4 模块的通用三段式:① 它的头文件里 uORB::Subscription 是谁(输入);② uORB::Publication 是谁(输出);③ SubscriptionCallbackWorkItem 订阅谁(谁唤醒它)。三段答完,模块在链路中的位置自动浮现。用这个方法读你自己的 my_first_app,它就是:订阅 sensor_combined、发布 lesson_report、靠 px4_poll 定时——没有回调,所以是最慢的 1 Hz。

二、动手:把链路钉在活系统上

  1. 起飞(仅仿真,真机勿试)。在运行 bin/px4 的主终端或 MAVLink shell:

    pxh> commander takeoff    # 观察日志直到 "Takeoff detected"

  2. 预测→实测频率。先凭"节拍器"原理预测哪环最快,再用 uorb top 实测,把结果填进链路图的实测表。重点看 vehicle_angular_velocity(陀螺仪,内环心跳)、vehicle_torque_setpoint 与 actuator_motors(应当几乎同频——直连)、以及你的 lesson_report(1 Hz,链路里最慢的蜗牛)。

  3. 悬停数值三连对答案。悬停稳定后开 MAVLink shell 连续执行:

    pxh> listener vehicle_rates_setpoint   # 滚转/俯仰/偏航期望 ≈ 0
pxh> listener vehicle_thrust_setpoint  # xyz[2] ≈ -0.60 ← 与 MPC_THR_HOVER 对上了!
pxh> listener actuator_motors          # control[0..3] 四个值 ≈ 0.6 附近,微抖

    -0.60 不是巧合:x500 机架文件(init.d-posix/airframes/4001_gz_x500)里 param set-default MPC_THR_HOVER 0.60。悬停推力 ≈ 悬停油门,链路理论和你第 7 课的启动链知识在此会师。

  4. 源码对号。打开 src/modules/mc_rate_control/MulticopterRateControl.cpp:126 看回调入口,跳到 :260/:264 看发布;再翻 mc_att_control.hpp:113/:115 与 ControlAllocator.hpp:178-187。注意 Run() 的写法和你第 4 课 ModuleBase 学的是同一个模式——阶段二不是白学的。

  5. 降落收工:

    pxh> commander land
pxh> commander disarm
✅ 本课的胜利:你手里现在有三份互相咬合的证据——官方概念图、uORB 实测数据、源码行号。下次读任何陌生模块(比如想改 ekf2 或加避障),用"三段式"十分钟就能说出它在链路里的位置。这是改控制代码之前最重要的防御性技能:先知道数据从哪来,再谈改它。

三、课后探索(可选)

重启 SITL 后试试调内环:param set MC_ROLLRATE_P 0.05(默认 0.15,削掉 2/3),再 commander takeoff——观察飞行器姿态的摆动和 rate_ctrl_status 的变化,体会"参数即控制律"。玩完 param reset MC_ROLLRATE_P 恢复。更进一步:官方 uORB Graph 页面把我们走通的这条链画成了可交互全图,找找你的 lesson_report 在不在上面(提示:它不在官方构建的图里,因为那是主分支的——这本身就是个值得想一想的发现)。
