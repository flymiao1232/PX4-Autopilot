第 2 课 · 手写你的第一个 PX4 应用

Mission:能独立改 PX4 代码 2026-10-31 · 约 30 分钟 · 路线:课程地图 · 上一课:第 1 课

上一课你运行了别人写好的 px4_simple_app。这一课你自己写一个——从零创建目录、三个文件、编译、运行,然后升级它去订阅真实传感器数据。这正是官方教程 Writing your First Application (Hello Sky) 的内容,我们按官方步骤走,但写一个属于你自己的新模块 my_first_app(不动仓库自带的示例)。

一、模块三件套:每个 PX4 模块的最小构成

一个能被编译、能运行的 PX4 模块,目录里只需要三样东西:

文件作用关键内容
xxx.c / xxx.cpp源代码入口函数 <名字>_main,__EXPORT 导出
CMakeLists.txt告诉构建系统怎么编译px4_add_module(...) 宏
Kconfig定义编译开关符号menuconfig EXAMPLES_XXX 布尔项

px4_add_module 的三个关键字段(以本课模块为例):

px4_add_module(
	MODULE examples__my_first_app   # 固件内部唯一名,约定:父目录前缀__模块名
	MAIN my_first_app               # shell 里的命令名,也是入口函数前缀
	SRCS my_first_app.c             # 源文件列表
)

第三个环节是"开关"如何接通,这是新手最容易卡住的地方:

boards/px4/sitl/default.px4board 中的
    CONFIG_EXAMPLES_MY_FIRST_APP=y
        │  (构建系统 cmake/kconfig.cmake 按符号名自动找目录)
        ▼
src/examples/my_first_app/   ← 你的三件套就放在这

规则:CONFIG_EXAMPLES_XXX 对应 src/examples/xxx(小写)。所以符号名和目录名必须对得上,改错一个字母,构建就会报 "Couldn't find path"。

二、动手 part 1:最小应用

  1. 创建模块目录:

    cd ~/PX4-Autopilot
mkdir -p src/examples/my_first_app

  2. 创建 src/examples/my_first_app/my_first_app.c,内容如下(许可证头从 官方教程 或任意现有源文件顶部复制——PX4 要求每个文件都有):

    #include <px4_platform_common/log.h>

__EXPORT int my_first_app_main(int argc, char *argv[]);

int my_first_app_main(int argc, char *argv[])
{
	PX4_INFO("Hello Sky!");
	return OK;
}

  3. 创建 src/examples/my_first_app/CMakeLists.txt:

    px4_add_module(
	MODULE examples__my_first_app
	MAIN my_first_app
	STACK_MAIN 2000
	SRCS
		my_first_app.c
	DEPENDS
	)

  4. 创建 src/examples/my_first_app/Kconfig:

    menuconfig EXAMPLES_MY_FIRST_APP
	bool "my_first_app"
	default n
	---help---
		Enable support for my_first_app

  5. 打开 boards/px4/sitl/default.px4board,在 CONFIG_EXAMPLES_HELLO=y 附近加一行:

    CONFIG_EXAMPLES_MY_FIRST_APP=y

  6. 编译:

    make px4_sitl_default

    这是增量构建,通常 1–2 分钟。如果报 Couldn't find path for ...,检查第 4、5 步的符号名和目录名是否完全一致(全小写)。

  7. 运行:

    ./build/px4_sitl_default/bin/px4
pxh> my_first_app

    预期输出 Hello Sky! ——这是你自己的代码在 PX4 里跑起来了。

三、动手 part 2:订阅真实传感器数据

只打印一行太无聊。现在把 my_first_app.c 的 main 函数体换成下面这样(订阅 sensor_combined,轮询 5 次,打印加速度计):

#include <px4_platform_common/px4_config.h>
#include <px4_platform_common/log.h>
#include <px4_platform_common/posix.h>
#include <poll.h>

#include <uORB/uORB.h>
#include <uORB/topics/sensor_combined.h>

__EXPORT int my_first_app_main(int argc, char *argv[]);

int my_first_app_main(int argc, char *argv[])
{
	PX4_INFO("Hello Sky!");

	/* subscribe to sensor_combined topic, limit to 5 Hz */
	int sensor_sub_fd = orb_subscribe(ORB_ID(sensor_combined));
	orb_set_interval(sensor_sub_fd, 200);

	px4_pollfd_struct_t fds[] = {
		{ .fd = sensor_sub_fd,   .events = POLLIN },
	};

	int error_counter = 0;

	for (int i = 0; i < 5; i++) {
		int poll_ret = px4_poll(fds, 1, 1000);

		if (poll_ret == 0) {
			PX4_ERR("Got no data within a second");

		} else if (poll_ret < 0) {
			if (error_counter < 10 || error_counter % 50 == 0) {
				PX4_ERR("ERROR return value from poll(): %d", poll_ret);
			}
			error_counter++;

		} else {
			if (fds[0].revents & POLLIN) {
				/* copy data into local buffer */
				struct sensor_combined_s raw;
				orb_copy(ORB_ID(sensor_combined), sensor_sub_fd, &raw);
				PX4_INFO("Accelerometer:\t%8.4f\t%8.4f\t%8.4f",
					 (double)raw.accelerometer_m_s2[0],
					 (double)raw.accelerometer_m_s2[1],
					 (double)raw.accelerometer_m_s2[2]);
			}
		}
	}

	return OK;
}

三行核心 API 对应第 1 课的三件套:orb_subscribe(订阅)、px4_poll(阻塞等待,不空转烧 CPU)、orb_copy(取数据)。

⚠️ 预期现象:不接仿真器时,加速度读数很可能是全 0 或超时——因为 SITL 的传感器数据由仿真器注入。让数据"活"起来(接 Gazebo)是第 3 课的内容,本课先确保链路通。

  1. 重新编译并运行:

    make px4_sitl_default
./build/px4_sitl_default/bin/px4
pxh> my_first_app

    预期:打印 5 行 Accelerometer: 0.0000 ...(数据为零属正常,见上方提示)。

✅ 本课的胜利:你在 PX4 源码树里从零创建了一个模块,接通 Kconfig → px4board 的编译开关,并在 shell 里运行了自己写的代码。从这一刻起,"改 PX4 代码"对你不再是理论。
