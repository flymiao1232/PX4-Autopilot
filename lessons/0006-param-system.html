上一课你的模块开始发布数据了,但行为还是写死的:想关掉打印只能重新编译。真实需求是"试飞时随时调":阈值、开关、周期都应该是参数——不改代码、不重编译,shell 里 param set 立即生效,还能存进存储器断电不丢。对应官方 Parameters & Configurations。这一课给 my_first_app 装上第一个参数 LR5_PUB_EN。

第 0 步 · 热身:抓一个 bug(5 分钟)

先运行上一课的模块,开一个 MAVLink shell:

pxh> my_first_app start
pxh> listener lesson_report    # 连续执行几次,盯住 sample_count

发现了么:sample_count 永远停在 1。回想第 5 课的语义——uORB 是 last-value-cached,所以能看到数据;但计数不涨的根因在你自己的代码:lesson_report_s report{} 声明在 while 循环内部,每次循环 {} 把结构体清零,再 sample_count++ 永远是从 0 到 1。

📌 修复(一行):你的 my_first_app.hpp 里已经躺着一个当时没派上用场的成员 uint32_t _sample_count{0}——它就是为这里准备的。把 cpp 里的 report.sample_count++; 改成 report.sample_count = ++_sample_count;。重新编译后再看 listener:计数每秒 +1。成员变量的生命周期跨循环迭代,循环内的局部变量每次都重生——这个坑在嵌入式里极其常见。

一、参数系统的三件事

参数比 topic 更省心,生命周期只有三件:

步骤做什么产物
1. 定义在模块目录建 *_params.c,用 PARAM_DEFINE_INT32(名字, 默认值) 写参数my_first_app_params.c
2. 收集构建时 px_process_params.py 自动扫描所有 *params.c,解析注释生成参数存储build/.../parameters.xml、px4_parameters.hpp
3. 读写代码里 param_find 拿句柄 + param_get 读值;shell 里 param set/show/save运行时行为可改、可存

三个已在 v1.17 源码核实的非显然事实:

  • *params.c 是被"解析"而不是被"编译"的。它里面没有 include、没有代码,只有 doxygen 注释 + PARAM_DEFINE_* 宏——构建脚本把它当元数据文本读(src/lib/parameters/CMakeLists.txt:119 用 GLOB 收集,所以不用改任何 CMakeLists)。对照第 5 课:msg 是显式注册列表,params 是自动收集,方向正好相反。
  • ⚠️ 最大的坑:GLOB 在 cmake 配置时求值。新建 params.c 后如果直接 make,参数很可能不存在——cmake 不知道有新文件了。症状:param_find 返回 PARAM_INVALID(定义见 src/lib/parameters/param.h:78)。对策:touch src/lib/parameters/CMakeLists.txt && make px4_sitl_default 强制重新配置(不行就 make clean 重来)。
  • 参数名 ≤ 16 个字符(src/lib/parameters/px4params/srcparser.py:370,超限直接报错),全大写 + 模块前缀是惯例,如 LR5_PUB_EN。
📌 参数 vs topic,一句判别法:参数是"配置"——慢变、有默认值、可持久化,回答"模块应该怎么工作";topic 是"数据"——快变、只留最新一份,回答"系统正在发生什么"。拿不准时问自己:这个值改了之后需要断电保存吗?

二、动手:给 my_first_app 加开关参数

  1. 新建 src/examples/my_first_app/my_first_app_params.c(不需要任何 include,全文件就这内容):

    /**
 * Enable lesson report publishing
 *
 * Set to 0 to stop publishing the lesson_report topic at runtime.
 *
 * @boolean
 * @group My First App
 */
PARAM_DEFINE_INT32(LR5_PUB_EN, 1);

    注释是元数据:@boolean 声明它是开关,@group 决定它在地面站参数树里的分组;宏的第二个参数 1 是默认值。参考实例:src/modules/land_detector/land_detector_params.c、src/modules/zenoh/zenoh_params.c。

  2. 强制重新配置并编译(第 1 次加 params.c 必做):

    touch src/lib/parameters/CMakeLists.txt
make px4_sitl_default

  3. 起 SITL,先验证参数本身存在(这一步和模块运不运行无关):

    pxh> param show LR5*        # 应看到 LR5_PUB_EN = 1

    如果报 "no params found",就是第 2 步的配置没生效,回去重来——这是你一定会遇到一次的坑,先认认它的样子。

  4. 改造 my_first_app.cpp(头文件不用动):

    // 顶部 include 区加:
#include <parameters/param.h>
    // run() 里,while 循环之前:查一次句柄(句柄不变,值会变)
	param_t pub_en = param_find("LR5_PUB_EN");

	if (pub_en == PARAM_INVALID) {
		PX4_ERR("LR5_PUB_EN not found");
		return;
	}
    // 循环内,px4_poll 之后:每轮读最新值
		int32_t pub_en_val = 0;
		param_get(pub_en, &pub_en_val);   // param set 立即生效的秘密

		if ((fds[0].revents & POLLIN) && pub_en_val) {   // ← 原 if 加条件

    用法对照真实模块:src/modules/uxrce_dds_client/uxrce_dds_client.cpp:1034 同款 param_get(param_find(...), &x);include 路径 <parameters/param.h> 对照 src/modules/mavlink/mavlink_main.h:62。

  5. 编译、运行、亲手拨动开关:

    pxh> my_first_app start
pxh> uorb top                  # lesson_report ~1 Hz
pxh> param set LR5_PUB_EN 0    # ★ 不用重启!uorb top 里 lesson_report 消失
pxh> listener lesson_report    # 还能打印!印证第5课:last-value-cached,旧值还在
pxh> param set LR5_PUB_EN 1    # 恢复发布
pxh> param save               # 持久化:重启 SITL 后仍是 1
pxh> param reset LR5_PUB_EN    # (可选)恢复代码里的默认值
✅ 本课的胜利:你的模块从"写死"变成了"可配置"。"定义参数 → 重新配置构建 → 运行时拨动"这条路上,唯一会咬人的就是 cmake GLOB 缓存那一口——咬过一次就免疫了。至此,阶段二只剩最后一课:启动流程(让模块开机自启)。

三、课后探索(可选)

真实模块并不每轮循环 param_get,而是继承 ModuleParams(px4_platform_common/module_params.h)+ 订阅 parameter_update topic,参数一变就被回调通知、缓存自动刷新。搜一下 DEFINE_PARAMETERS 看 mc_att_control 的写法——那是 C++ 主流写法,本课 C API 是它的底层。想想:本课"循环内每轮读"的方案在什么频率下会变成浪费?
