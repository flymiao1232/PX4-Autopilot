第 1 课 · PX4 的骨架:模块、uORB 与 Shell

Mission:能独立改 PX4 代码 2026-10-31 · 约 15 分钟 · 配套参考:课程地图 · 术语表

改 PX4 代码之前,你需要一个正确的心智模型。好消息是:这个模型只需要一句话——

PX4 是一组互相独立的小程序(模块),它们不互相调用函数,而是通过一个叫 uORB 的消息总线发布/订阅数据。

记住这句话,你看任何 PX4 代码都会问三个问题:这个模块订阅什么?发布什么?我能在 shell 里怎么运行它?本课就建立这三个直觉。

一、数据是怎么流动的

以多旋翼的姿态控制为例,一条真实的数据流水线(箭头 = uORB topic):

sensors ──> sensor_combined ──> ekf2 ──> vehicle_attitude ──> mc_att_control ──> actuator_motors
 (融合原始传感器)   (IMU 融合数据)      (状态估计)      (姿态四元数)        (姿态控制器)      (电机输出)

每个方框都是一个模块:独立的可执行程序,在 PX4 shell(pxh>)里就是一个命令。模块之间唯一的耦合就是 topic——这就是为什么改 PX4 通常是"加一个新模块,订阅别人的 topic,发布一个新 topic",而不是去改别人的代码。官方的系统架构图解见 PX4 Flight Stack Architecture(v1.17)。

完整的数据流关系图见 uORB Graph(本仓库:docs/en/middleware/uorb_graph.md)。

二、代码在哪:目录地图

这是本仓库(v1.17)的真实顶层结构,先把地图装进脑子:

目录装的是什么举例
src/modules/飞行与控制相关的主模块ekf2、mc_att_control、commander
src/drivers/硬件驱动(IMU、磁力计、PWM…)imu、magnetometer、pwm_out
src/examples/学习用示例(你的第一个模块放这里)px4_simple_app、work_item
src/templates/正式模块模板(带 start/stop)template_module
src/lib/共享库(数学、矩阵、geo…)matrix、lib/mathlib
src/systemcmds/shell 命令工具param、listener、uorb、top
msg/所有 uORB topic 的定义(.msg)vehicle_attitude.msg
boards/板级配置(px4board)px4/sitl/default.px4board
ROMFS/启动脚本与默认参数px4fmu_common/init.d

三个必背事实:

  • 一个模块 = 一个目录,里面至少一个源文件 + 一个 CMakeLists.txt。编译进 PX4 靠 px4_add_module(...) 这个 CMake 宏。
  • 模块的入口函数必须叫 <模块名>_main,并用 __EXPORT 导出——shell 才能把它当命令运行。
  • topic 的类型定义在 msg/*.msg,编译时自动生成 C 结构体和 ORB_ID(xxx) 常量。想传自定义数据?加一个 .msg 文件就行。

三、uORB 三件套与三个调试命令

C API 核心就三个动作(以 src/examples/px4_simple_app/px4_simple_app.c 为实例):

  • 发布:orb_advertise(ORB_ID(vehicle_attitude), &att) 注册话题,orb_publish(...) 发数据。
  • 订阅:orb_subscribe(ORB_ID(vehicle_acceleration)) 拿到句柄,orb_copy(...) 取数据。
  • 等待:用 px4_poll() 阻塞等数据,避免空转烧 CPU。

在 shell 里观察 uORB 的三个必备命令:

pxh> uorb top              # 各 topic 的发布频率与 CPU 占用
pxh> uorb list              # 当前存在的全部 topic
pxh> listener sensor_combined  # 打印某个 topic 的最新数据

更多调试技巧见 uORB 调试文档(本仓库 docs/en/debug/sensor_uorb_topic_debugging.md)。

四、动手:15 分钟内跑通你的第一个 PX4 应用

你的机器上已经有 build/px4_sitl_default 构建产物,示例模块 px4_simple_app 也已在默认 SITL 配置中启用——直接开跑。

  1. 确认增量构建可用(第一次全编要较久,之后通常一分钟内):

    cd ~/PX4-Autopilot
make px4_sitl_default

  2. 单独启动 PX4 主程序,进入 pxh> shell(不接仿真器,纯控制台):

    ./build/px4_sitl_default/bin/px4

  3. 看看"命令列表"其实就是模块列表:

    pxh> help

  4. 观察 uORB 总线上正在发生什么:

    pxh> uorb top

    注意:此时没有仿真器连接,部分传感器数据可能是零值或静止——先熟悉界面即可,下一课接 Gazebo 看"活"的数据。

  5. 运行你的第一个应用:

    pxh> px4_simple_app

    预期输出 Hello Sky! 和几行姿态数据。

  6. 这个应用是怎么写的?打开源码对照刚学的三件套:

    code src/examples/px4_simple_app/px4_simple_app.c

    找到 orb_subscribe、orb_advertise、px4_poll 三行,理解它订阅了加速度、发布了姿态。

  7. 输入 exit 退出。

✅ 本课的胜利:你启动了 PX4,用 uorb top 看到了模块间的数据流,并在 shell 中运行了第一个应用。至此你已经拥有了"地图 + 导航工具"。
