关键事实(都是踩坑点)

事实出处
rcS 由宿主机 /bin/sh 执行,px4-alias.sh 翻译 NuttX 语法platforms/posix/.../main.cpp:546
SITL 一模块一进程:bin/ 下每个模块一个 px4-* 可执行文件build/px4_sitl_default/bin/
rcS 首行 set +e:模块 start 失败不中止开机,只写日志init.d-posix/rcS:6
机架文件名 = <ID>_<模型名>,ID 即 SYS_AUTOSTARTinit.d-posix/airframes/4001_gz_x500
ROMFS 源目录改动后必须 make 才会拷进 build/etcinit.d-posix/CMakeLists.txt:37 px4_add_romfs_files
改 ROMFS/源文件,别改 build/ 副本(下次构建被覆盖)—

自启挂载点速选

需求写在哪
所有 SITL 机型都自启ROMFS/px4fmu_common/init.d-posix/rcS 尾部(boot_complete 之前)
只在某机型自启该机型的机架文件,如 init.d-posix/airframes/4001_gz_x500
真实硬件不改固件SD 卡 /fs/microsd/etc/extras.txt(开机末尾自动 source,init.d/rcS:599)
整场换掉启动脚本(最小复现)bin/px4 -s my_script.txt

rcS 常用语法糖

param set-default NAME val   # 设默认值:仅在参数未存过值时生效
param set NAME val           # 强制设值(覆盖已存的)
param compare -s NAME val    # 相等则返回真 → 用作 if 守卫(-s:静默)
set VAR val  /  $VAR         # 脚本变量(px4-alias.sh 翻译成 shell 变量)
. file                       # source 另一个脚本(rcS 的灵魂)
command &                    # 后台启动(如 ekf2 start &)

自启排障三连

  1. 翻主终端(运行 bin/px4 那个)的启动日志——自启失败只在这里留痕。
  2. pxh> 里 <模块> status:模块自己汇报活没活。
  3. pxh> 里 uorb top:该模块的 topic 有没有在发布。
